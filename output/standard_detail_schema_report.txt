6. OPAQUE / ENCRYPTED IDENTIFIERS
----------------------------------
The response contains:
- standardEncId
- standardEncIId
- departmentEncId
- committeeEncId
- reviewId

They are string values with encrypted/opaque token structure and are used by the frontend as references or route/query identifiers. They are not directly human-readable IDs. The report does not decrypt them.

The frontend uses the encrypted review identifier for review-related calls and uses encrypted standard identifiers in navigation/detail routes where available. These values may therefore be required by related APIs even when standardId is available.

9. CORE RECORD SUFFICIENCY
--------------------------
The primary detail endpoint is sufficient for a minimal core record containing:
- numeric standard identity
- standard number
- standard title/name
- department ID and display name
- committee ID and display name
- opaque detail/review references

It is not sufficient by itself for a complete metadata record containing publication date, lifecycle, revisions, amendments, referred standards, product manuals, certification, licences, laboratories, classification, ICS, SDG, language, or type/category. Additional endpoint calls are mandatory for those areas where the data is required.

The raw list dataset already contains publishedOn for list records, but publishedOn was not returned by the tested primary detail response.
